# Лабораторна робота №5. Використання Vue composable

## 1. Структура компонентів та модулів

Застосунок побудований на базі Vue 3 (Composition API, `<script setup>`) із чітким розподілом відповідальності між UI-компонентами та composables:

```text
src/
├── api/
│   └── products.js — Формування реактивного URL через URLSearchParams (limit=12, skip, delay=1500, q)
├── components/
│   ├── ProductSearchForm.vue — Поле пошуку з контрактом v-model та статусом оновлення (без HTTP і таймерів)
│   ├── ProductCatalog.vue — Сітка товарів, скелетони початкового завантаження, стани помилки та порожньої видачі
│   ├── ProductCard.vue — Представлення однієї картки товару та форматування ціни
│   └── CatalogLoadMore.vue — Нижній маркер дозавантаження, прогрес і події load-more та retry
├── composables/
│   ├── useFetch.js — HTTP-запит через watchEffect і toValue(), AbortController та методи abort / refetch
│   ├── useDebouncedValue.js — Відкладене оновлення значення (400 мс) з очищенням попереднього таймера
│   └── useIntersectionObserver.js — Підписка на перетин нижнього маркера після монтування та disconnect()
├── styles/
│   └── main.css — Оригінальні BEM-стилі стартера
├── App.vue — Кореневий компонент, що поєднує стан пошуку, пагінації, composables та об'єднання сторінок
└── main.js — Точка входу застосунку
```

## 2. Версії залежностей

Проєкт використовує наступні версії ключових технологій:

* **Node.js**: 24.x LTS
* **Vue**: ^3.5.x
* **Vite**: ^6.x / ^5.x (за конфігурацією стартера)
* **API**: DummyJSON Products API (`https://dummyjson.com`)

## 3. Команди запуску та збірки

Встановлення всіх необхідних залежностей відповідно до `package-lock.json`:

```bash
npm ci
```

Запуск локального сервера для розробки:

```bash
npm run dev
```

Створення оптимізованої виробничої збірки проєкту:

```bash
npm run build
```

Локальний перегляд зібраного проєкту:

```bash
npm run preview
```

## 5. Схема потоку стану та обґрунтування меж відповідальності

### Схема потоку стану

```text
query (сирий ввід)
  ├──(watch, flush: 'sync')──▶ abort() активного запиту
  └──(debounce 400 мс)──▶ debouncedQuery ──▶ скидання skip=0, products=[], total=0
                                                   │
нижній маркер ──▶ load-more ──▶ skip + 12 ─────────┴──▶ requestUrl (computed)
                                                             │
                                                             ▼
                                                        useFetch(requestUrl)
                                                             │
                                                             ▼
                                                   merge page (без дублікатів id)
                                                             │
                                                             ▼
                                                         products
```

### Пояснення меж відповідальності та очищення ресурсів

* **Чому `ProductSearchForm` не формує URL:** форма працює за чистим контрактом `v-model` і відповідає лише за введення та доступність. Це дозволяє змінювати правила API або перевикористовувати форму без редагування її шаблону.
* **Чому `ProductCatalog` не завантажує дані:** компонент відповідає виключно за представлення переданого масиву товарів та UI-станів (скелетони, помилка, порожній результат) і не залежить від способу отримання даних.
* **Чому `debounce` не замінює `abort`:** `debounce` лише відкладає створення *нового* запиту на 400 мс, але не зупиняє запит, що *вже виконується* в мережі (із затримкою 1500 мс). Синхронний виклик `abort()` при зміні сирого `query` негайно скасовує застарілий запит і захищає каталог від перезапису свіжих даних повільною старою відповіддю.
* **Чому очищення ресурсів належить composables:** модуль, який створив ресурс (таймер у `useDebouncedValue`, `AbortController` у `useFetch`, екземпляр `IntersectionObserver` у `useIntersectionObserver`), зобов'язаний сам гарантувати його звільнення через `onCleanup`, `onBeforeUnmount` або `onScopeDispose`. Компоненти залишаються чистими й захищеними від витоків пам'яті.

| **Дозавантаження 2-ї сторінки** | Прокручування додає сторінку з `skip=12`, попередні картки не зникають, `id` не повторюються. | `https://dummyjson.com/products?limit=12&skip=12&delay=1500` | 24 | Сітка розширилась до 24 карток, нижній блок оновив прогрес |
