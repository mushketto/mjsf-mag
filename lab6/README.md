# Лабораторна робота №6. Робота з Vue Router

## 1. Структура проєкту

Застосунок побудований на базі Vue 3 (Composition API, `<script setup>`) та Vue Router 4.6.4 із розділенням на оболонки (`layouts`), представлення (`views`), перевикористовувані компоненти (`components`) та композиційні функції (`composables`):

```text
src/
├── api/
│   └── products.js — Формування URL каталогу й товару через URLSearchParams та валідація числового id
├── router/
│   └── index.js — Конфігурація createRouter, createWebHistory, вкладених маршрутів, redirect, catch-all і meta.breadcrumb
├── layouts/
│   ├── ProductsLayout.vue — Оболонка розділу /products із вкладеним RouterView
│   └── ProductLayout.vue — Спільна оболонка товару: завантаження за id, стани 404/помилки, крихти та передача product через слот RouterView
├── views/
│   ├── ProductCatalogView.vue — Каталог із пошуком, синхронізацією query.q (replace/refetch) та дозавантаженням
│   ├── ProductOverviewView.vue — Представлення опису й характеристик товару (отримує product пропсом)
│   ├── ProductReviewsView.vue — Представлення відгуків покупців або порожнього стану (отримує product пропсом)
│   ├── AboutView.vue — Інформаційна сторінка про застосунок
│   └── NotFoundView.vue — Сторінка 404 для невідомих маршрутів
├── components/
│   ├── Breadcrumbs.vue — Відображення хлібних крихт за WAI-ARIA (nav, ol, RouterLink, aria-current="page")
│   ├── ProductSearchForm.vue — Поле пошуку з контрактом v-model та статусом оновлення
│   ├── ProductCatalog.vue — Сітка товарів, скелетони, помилка та порожній стан
│   ├── ProductCard.vue — Картка товару з переходом на product-overview і збереженням query.q
│   └── CatalogLoadMore.vue — Нижній маркер дозавантаження з IntersectionObserver
├── composables/
│   ├── useBreadcrumbs.js — Побудова масиву крихт за route.matched, meta.breadcrumb і реактивною назвою товару
│   ├── useFetch.js — HTTP-запит із підтримкою null URL, очищенням старих даних, AbortController і збереженням HTTP-статусу
│   ├── useDebouncedValue.js — Відкладене оновлення значення (400 мс) з очищенням таймера
│   └── useIntersectionObserver.js — Спостереження за нижнім маркером та disconnect() при розмонтуванні
├── styles/
│   └── main.css — BEM-стилі каталогу, навігації, хлібних крихт і сторінки товару
├── App.vue — Загальна оболонка застосунку (шапка, основна навігація, зовнішній RouterView, підвал)
└── main.js — Ініціалізація Vue та підключення маршрутизатора (app.use(router)) до монтування
```

## 2. Версії залежностей

Проєкт використовує наступні версії ключових технологій:

* **Node.js**: 24.x LTS
* **Vue**: ^3.5.x
* **Vue Router**: 4.6.4 (зафіксовано через `--save-exact`)
* **Vite**: за конфігурацією стартера
* **API**: DummyJSON Products API (`https://dummyjson.com`)

## 3. Команди запуску та збірки

Встановлення залежностей відповідно до `package-lock.json`:

```bash
npm ci
```

Запуск локального сервера для розробки:

```bash
npm run dev -- --port 5176 --strictPort
```

Створення оптимізованої виробничої збірки проєкту:

```bash
npm run build
```

Локальна перевірка зібраного проєкту (у тому числі прямих вкладених адрес та reload):

```bash
npm exec vite preview -- --port 5176 --strictPort
```

## 4. Дерево маршрутів

```text
/                              ──▶ redirect { name: 'products' }
/products                      ──▶ ProductsLayout (meta.breadcrumb: 'Каталог')
├── ''                         ──▶ ProductCatalogView [name: 'products']
└── :id                        ──▶ ProductLayout (meta.breadcrumb: dynamic 'product')
    ├── ''                     ──▶ ProductOverviewView [name: 'product-overview']
    └── reviews                ──▶ ProductReviewsView [name: 'product-reviews'] (meta.breadcrumb: 'Відгуки')
/about                         ──▶ AboutView [name: 'about'] (meta.breadcrumb: 'Про застосунок')
/:pathMatch(.*)*               ──▶ NotFoundView [name: 'not-found'] (meta.breadcrumb: 'Сторінку не знайдено')
```

## 5. Відповідальність модулів

| Модуль | Входи | Виходи | Власний стан | Відповідальність |
| :--- | :--- | :--- | :--- | :--- |
| **`router/index.js`** | Конфігурація маршрутів, `BASE_URL` | Екземпляр `router` | Історія HTML5 (`createWebHistory`) | Зіставлення URL із компонентами, вкладеність `children`, перенаправлення та catch-all 404 |
| **`App.vue`** | Поточний маршрут через `RouterView` | Основна навігація `RouterLink` | Немає | Загальна оболонка сторінки: шапка, навігація, зовнішній `RouterView` та підвал |
| **`ProductsLayout.vue`** | Вкладені маршрути `/products` | Внутрішній `RouterView` | Немає | Спільний рівень ієрархії для каталогу та сторінки товару |
| **`ProductLayout.vue`** | `route.params.id`, `route.query.q` | Пропс `product` через слот `RouterView`, `items` для `Breadcrumbs` | `product`, `isLoading`, `error` (через `useFetch`) | Валідація `id`, завантаження товару, стани 404/помилки, спільна картка товару й навігація між оглядом і відгуками |
| **`ProductCatalogView.vue`** | `route.query.q`, події дочірніх компонентів | `router.replace(...)`, пропси для форми, каталогу та `CatalogLoadMore` | `query` (чернетка), `editVersion`, `skip`, `products`, `total` | Координація пошуку, двостороння синхронізація з `query.q`, скасування запитів і пагінація |
| **`ProductOverviewView.vue`** | Пропс `product` (обов'язковий) | Розмітка опису й характеристик | Немає | Представлення опису та технічних характеристик без власних HTTP-запитів |
| **`ProductReviewsView.vue`** | Пропс `product` (обов'язковий) | Список відгуків або порожній стан | Немає | Представлення відгуків покупців із форматуванням дати без власних HTTP-запитів |
| **`AboutView.vue` / `NotFoundView.vue`** | `useRoute()`, `useBreadcrumbs()` | Розмітка сторінки та `RouterLink` до каталогу | Немає | Відображення відомостей про застосунок або стану невідомого маршруту 404 |
| **`useBreadcrumbs.js`** | Необов'язковий `productTitle` (`MaybeRefOrGetter`) | `computed`-масив `{ label, to }` | Немає | Обчислення ланцюжка крихт за `route.matched` із підстановкою назви товару та збереженням `query.q` |
| **`Breadcrumbs.vue`** | Пропс `items` | Розмітка `nav > ol > li` з `RouterLink` | Немає | Доступне відображення хлібних крихт (попередні рівні — посилання, поточний — текст з `aria-current="page"`) |
| **`useFetch.js`** | `url` (`MaybeRefOrGetter<string \| null>`) | `data`, `error`, `isLoading`, `abort`, `refetch` | Контролер запиту, `reloadToken` | Завантаження даних, очищення застарілого стану, збереження HTTP `status` і захист від race condition |

## 6. Правила метаданих хлібних крихт (`meta.breadcrumb`)

Хлібні крихти обчислюються в `useBreadcrumbs` на основі масиву `route.matched` (від батьківського запису до дочірнього), а не об'єднаного `route.meta`, оскільки `route.meta` виконує поверхневе злиття й перезаписує ключ `breadcrumb` останнім дочірнім маршрутом.

| Запис маршруту | Значення `meta.breadcrumb` | Примітка щодо формування |
| :--- | :--- | :--- |
| `/products` (`ProductsLayout`) | `{ label: 'Каталог', name: 'products' }` | Зберігає поточний `query.q` у цілі посилання `to` |
| Порожній дочірній `''` каталогу | *Не задається* | Пропускається, щоб рівень «Каталог» не дублювався |
| Дочірній `:id` (`ProductLayout`) | `{ dynamic: 'product', name: 'product-overview' }` | До відповіді API — «Товар №`<id>`», після завантаження — `product.title`, за відсутності — «Товар не знайдено» |
| Порожній дочірній `''` огляду | *Не задається* | Пропускається, щоб рівень товару не дублювався |
| Дочірній `reviews` | `{ label: 'Відгуки', name: 'product-reviews' }` | Поточний рівень на сторінці відгуків (`aria-current="page"`) |
| `/about` | `{ label: 'Про застосунок', name: 'about' }` | Окремий кореневий рівень |
| `/:pathMatch(.*)*` | `{ label: 'Сторінку не знайдено', name: 'not-found' }` | Окремий рівень для невідомої адреси |

## 7. Розподіл стану та вимоги до виробничого сервера

### Розподіл стану між `params`, `query` і завантаженим товаром

* **Динамічний параметр `params.id`** визначає ідентичність конкретного ресурсу в шляху URL (`/products/12`, `/products/12/reviews`). Перед запуском запиту виконується валідація на додатне ціле число; некоректне значення передає `null` у `useFetch` і не створює мережевого запиту.
* **Параметр запиту `query.q`** зберігає підтверджену умову пошуку, яку можна передавати посиланням, оновлювати через `F5` і відновлювати кнопками історії браузера. Поле вводу (`query`) виступає локальною чернеткою: під час редагування активний запит скасовується синхронно, а після паузи 400 мс адреса оновлюється через `router.replace()` без засмічення історії переходів. Якщо користувач скасував запит і повернувся до попереднього тексту `q`, після паузи виконується явний `refetch()`.
* **Завантажений товар (`product`)** належить спільній оболонці `ProductLayout`, яка завантажує його один раз для поточного `id` і передає дочірнім представленням (`ProductOverviewView`, `ProductReviewsView`) через слот `<RouterView v-slot="{ Component }">`. Завдяки цьому перемикання між оглядом і відгуками не повторює HTTP-запит, а зміна `id` у тому самому екземплярі оболонки оновлює дані та скасовує попередній запит.

### Вимоги до виробничого сервера з `createWebHistory`

У режимі HTML5 history (`createWebHistory`) адреси на кшталт `/products/12` або `/products/12/reviews` виглядають як звичайні шляхи на сервері. Локальний `vite preview` обробляє їх автоматично, однак на виробничому вебсервері (Nginx, Apache, Caddy, Netlify тощо) необхідно налаштувати **SPA fallback-правило**: для будь-якого запиту, який не відповідає реальному статичному файлу (`.js`, `.css`, зображення) або маршруту API, сервер повинен повертати головний `index.html`, після чого Vue Router на клієнті зіставить маршрут і покаже потрібне представлення або сторінку 404.

| 3 | Пряме відкриття огляду й відгуків | Прямі адреси відкриваються в новій вкладці й після `F5` без відвідування каталогу | Відповідає очікуваному | `/products/12`, `/products/12/reviews` | 1 на вкладку |
